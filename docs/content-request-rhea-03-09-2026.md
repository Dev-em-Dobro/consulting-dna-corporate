## How to use this

**1. Start with Part 1.** You mentioned wanting to cut some screens from the menu. Please tell us
which ones go before you write anything — every screen you remove is content you don't have to
produce. Nothing else in this document matters until that's settled.

**2. Then work through Part 2**, page by page. It runs in the order the page itself runs, top to
bottom. Each block gives you two things:

- **A label line** — the name of the block, its character ceiling, and what that block has to do for
  the reader.
- **The words that are on the page right now**, as an ordinary paragraph underneath.

**Edit that paragraph directly.** Type over it, cut it, rewrite it — we hold the original, so nothing
you delete is lost. Where a block is empty today it says so, and there is a line marked **→** for you
to write on. Where a block needs nothing from you, it says that too — skip it.

There are no boxes to write inside. A 500-character answer needs the full width of the page, not a
narrow column.

**3. For images, skip Part 2 and go to Part 3.** The image notes in Part 2 are only there so you can
see what each block needs. You don't have to work from them — **Part 3 is a numbered list of the
actual shots we're asking for**, and all you do is find the closest thing you have for each number.
Deciding which photograph ends up where is our job, not yours.

### About the character counts

You asked us to be prescriptive, so every block has a number. One thing to be clear about, because it
changes how you should use them:

> **The number is a layout ceiling, not a writing target.** It's the point past which the block breaks
> visually. If an idea genuinely needs more, write more and flag it — we'll change the design to hold
> it. What we can't do is design a block before we know roughly how much goes in it.

The scale, so it's consistent across the whole site:

| Element | Max characters |
|---|---|
| Eyebrow (the small label above a headline) | 30 |
| Page title | 60 |
| Line under the page title | 140 |
| Section headline | 70 |
| Short intro line | 200 |
| Body paragraph | 500 |
| Pull quote / testimonial | 200 |
| Metric label | 60 |

## Part 5 — What you'll be able to change yourself

Worth saying plainly, because it decides how much of a system you have to learn: **not every page is
meant to be self-service, and that's deliberate.**

| You edit it yourself, in the CMS | We edit it for you |
|---|---|
| Case studies · Solutions · Insights · Partnerships · Team members · the firm-level statistics · the awards ticker · offices and regions | Home page copy · Our Identity · Our Approach · the framing text on Our Clients and Our Impact |

The line is drawn by **how often a thing changes**, not by how important it is. Anything that grows —
a new case, a new insight, a new person — is a list, and lists belong in a CMS where you add to them
without us. Anything written once and rarely touched — your purpose, your story, why you're different
— lives in the build, where we can typeset it properly.

Two consequences worth knowing now rather than later:

- **You won't need a CMS tutorial to launch.** Everything in Parts 1–3 comes to us through this
  document and we publish it. No new tool to learn this week.
- **The pages we hold need us to change them.** Today that costs nothing — you ask in the group, it's
  live the same day. Six months from now, if you want to reword the homepage on a Sunday, it still
  goes through us. If any specific block feels like something you'll want to change on your own,
  tell us which and we'll move it into the CMS before launch rather than after.
